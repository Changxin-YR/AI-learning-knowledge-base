# API

Base prefix: `/api/v1`. OpenAPI is available at `/docs` when the server runs.

Implemented routes include `/health`, `/ready`, `/auth/demo`, `/auth/register`, `/users/me`, knowledge-base/document CRUD, `/chat`, `/chat/stream`, conversations, learning plans/tasks, quizzes/submit, mastery, knowledge graph, stats, repository import, memories CRUD/search, agent tool schemas, `/agents/run`, and `/agents/runs`. Bearer JWT is required for user resources; ownership is checked server-side. Quiz creation returns questions and options only; answers are evaluated on submit. Repository import clones only public GitHub/GitLab/Gitee repositories with depth 1, no submodules, DNS/IP checks, size/file limits, static analysis only, and indexes selected text files into a knowledge base. Agent runs accept validated structured tool calls and record tool audit rows; with the three `OPENAI_*` variables configured they also execute an OpenAI-compatible tool-calling loop, otherwise explicit structured calls are required.

`/chat` and `/chat/stream` retrieve first and then answer: with the three `OPENAI_*` variables configured and `DEMO_AI_MODE=0` the configured model generates the answer strictly from the retrieved passages and must reply `NOT_ENOUGH_EVIDENCE` when they are insufficient, in which case the response carries no citations (fail-closed). Otherwise the deterministic cited excerpt is returned. `CHAT_TIMEOUT_SECONDS` (default `60`) bounds the generation call.
